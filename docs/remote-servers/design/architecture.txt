1. RECOMMENDED ARCHITECTURE
Keep one authoritative Tofu apiPlugin, one application listener, one SQLite library and one torrent worker per hosting instance. Both local desktop workspace and remote browsers load that host's same-origin Furin application. The native process owns a separately packaged connection manager and remote-window lifecycle; it never proxies application API calls and never rewrites src/lib/client.ts. The manager can run with no hosting backend at all. Remote windows are sandboxed, isolated by server/device account, and do not expose native RPC to remote pages.

Separate three identities explicitly:
- Server: random stable serverId, persisted transactionally with the hosting database; independent of IP, origin and display name.
- Authorized device: stable deviceId + current grant/role + session family. Credentials may rotate without changing idempotency identity.
- Local client installation: separate native catalog, selected host, device-specific preferences and secure credential references; present even with local hosting disabled.
No cross-server library merging. IDs, state and mutations are always scoped to the selected server. TLS validates transport identity; public serverId is a routing consistency check, not cryptographic proof.

Rejected alternative: building a detached universal SPA that sends Eden to arbitrary hosts. It conflicts with the protected same-origin client, requires CORS/cookie changes, and creates version skew between remote frontend/backend. Rejected alternative: a localhost reverse proxy or second Elysia application for remote traffic. It violates the one-listener/client contract and confuses identity and native privilege.

3. AUTHORIZATION THAT PRESERVES THE PROTECTED EDEN CLIENT
This is the key design decision: direct in-process Eden has NO requesting user's session. Never synthesize it via AsyncLocalStorage, forwarded cookies, a custom fetcher, global mutable current-user state or an internal HTTP request.

3.1 Explicit data classes
A. Shared library reads: every authenticated Playback client gets the exact same safe DTO. SSR and browser responses for those endpoints have identical shape and privilege. New safe dashboard contains server public identity, safe torrent summaries, safe destination IDs/names/icons, playback availability and safe aggregate transfer counts. Exclude settings, local paths, peer IPs, tracker credentials/URLs with tokens, magnet/private torrent internals, activity history containing host paths, credential config and native-capability claims. Make safe detail/file DTOs too; do not spread internal objects and try to blacklist fields. Use explicit projection processing (allowed by the no-trivial-wrapper rule).
B. Administrative/shared privileged reads: own endpoint and page subtree, authorized independently at network API and resolved Furin page boundary. These may use direct Eden SSR after their page grant was checked. Their output is common to all callers authorized for that endpoint; never device-personal data. Prefer browser fetch for marginal privileged panels to keep SSR audit smaller.
C. Device-personal reads (/api/session, own playback progress, personal preference/profile grants): browser-only existing shared Eden calls after mount. Direct in-process reads to 'current session' return a typed unavailable-context failure; they never return a privileged default identity. Initial SSR renders common data and a neutral/pending capability state. UI waits for current session before enabling privileged/local actions. Browser already sends same-origin cookies through the unchanged client.

Root layout must stop treating dashboard.settings.theme or session.mode as client identity. Appearance uses a minimal local preference pre-hydration bootstrap scoped to origin/server, or neutral SSR followed by client preferences; it must not read server admin settings. Split server settings (paths, torrent limits, automation) from local appearance/player options. Loading capability state cannot flash admin buttons. These are required UI changes, not merely security notes.

3.2 Concrete framework authorization extension
Add a public immutable dispatch context associated with Request via framework-owned WeakMap, populated at desktopApp's first outer wrapper. Contract sketch: dispatchContext(request) => {kind:'network', server, peerAddress, connectionSignal} | {kind:'in-process'}. The network kind comes ONLY from the Bun listener's actual Server argument verified against app.server, never headers, Host, query, a public decorator or an arbitrary context field. Unknown supplied server arguments fail closed. Direct Eden receives in-process identity and may execute shared server-side reads, but is not a device and cannot execute local UI actions. Preserve metadata across framework-created Requests explicitly via internal transfer, not copied user headers. This needs integration proof in Bun JIT/AOT/promoted response paths. Do not expose a mark-as-trusted API to browser code.

Add optional Furin page authorization contract (name can be finalize after review): authorizePage(context, resolved) -> undefined | typed Elysia status/problem. resolved includes stable framework routeId/pattern and transport ('document'|'navigation-data'), computed AFTER framework parse/normalization/matching and BEFORE any root/parent/leaf loader, cache read, rendering, deferred task creation or not-found root render. The callback receives the ORIGINAL network request, not the synthetic logical request. Tofu uses explicit routeId/pattern permission policy with deny-by-default for new private page categories. If using metadata, declare metadata on real registered routes; never trust policy from a query or client. Do not implement this with string-prefix matching of unvalidated ?path= values. Invalid path fails parser before policy; unknown paths use a safe public error root without private root loader.

For installed Furin, call the hook in createDataEndpoint after matching and before resolve/render/loaders; call it in document and cached document dispatch. Preserve incoming abort/revocation signal on synthetic requests (currently omitted). If choosing the newer native-route Furin transport instead, explicitly migrate/pin that release and prove equivalent checks on ?_furin=data; don't mix two protocols accidentally.

Every API endpoint still has a typed network grant guard on its own Elysia plugin/route; data-page gating does not replace API checks. The admission hook authenticates on every request. Permission checks must happen BEFORE sync idempotency replay so a previously successful result cannot bypass a later downgrade. All personalized and privileged HTML/data/API responses use private,no-store; disable ISR/SSG/PPR/page result caching for private Tofu pages in v1. Server caches may hold internal library snapshots but only explicit safe projections leave viewer endpoints. Furin query hydration must only contain safe projected endpoint bodies; audit __furinQueries/deferred frames, not only the returned loader object.

3.3 In-flight authorization
Admission records deviceId and grantVersion, registers an AbortController under that device, and composes request disconnect + revocation + server shutdown signals. Revocation or downgrade increments durable authorization version, closes affected sync/SSE/media/deferred readers and prevents further emissions. Recheck version before releasing a delayed privileged result/chunk. Bytes already delivered cannot be recalled; documentation must not imply otherwise. Browser handling of 401/403 clears private caches and never renders a previously cached admin view as authorized. Desktop forget destroys that server partition.

4. FRAMEWORK/NATIVE HOST CONTRACTS AND PROOF GATES
Rebuild the inflexible single-backend-window assumption in electrobun runtime/standard-host, while preserving existing local-only startup behavior as default. Do not add backend-aware wrappers around every call.

Required extension surfaces:
- Backend listen configuration: hostname/port/TLS + advertised canonical origin passed into existing host startup, using the SAME exported apiPlugin. server.ts still owns standalone listen/shutdown; desktop host owns desktop listen/shutdown as it does today. No app factory.
- Network admission policy: replace mandatory desktop-cookie-only rejection with app-approved remote device authentication AND distinct host-issued local-window capability. Preserve low-level dispatch integrity check. Merely turning restrictWebToLoopback off does not enable secure sharing.
- Same-listener local-window bootstrap: remove startSessionBootstrap's Bun.serve. Host creates high-entropy, short-lived, one-use grant in memory and opens a minimal /connect/local#grant page on apiPlugin; script removes fragment, POSTs it same-origin, receives HttpOnly cookie and navigates. The page is a tiny public bootstrap document without Tofu root loaders, third-party scripts, referrers or caching. Token redemption rejects wrong origin/invalid content type, uses constant-time/hash comparisons and atomic one-use claim, binds to intended host window/session, never upgrades a normal remote pairing credential. A native Session cookie API can install the issued cookie directly instead after verification; there is still no bootstrap listener. Local insecure loopback uses an explicit separate local-cookie name/transport contract; Secure cookies remain mandatory for remote HTTPS. Prefer HTTPS even for local workspace while sharing is enabled to avoid dual protocols on one listener.
- Host shell entry separate from server entry: load packaged manager assets, native catalog, secure store, optional backend supervisor first. Dynamically import the server ONLY when local hosting is enabled. Client-only startup must not import apiPlugin, database-plugin, instance lease, torrent worker or setup that starts them. Bundler/codegen entry graph must prove this, not a runtime flag after imports. Server startup failure prevents its workspace opening; the already valid independent connection manager remains usable and shows failure.
- Remote workspace API input: verified serverId, selected HTTPS origin, partitionId, native-owned display label, navigation policy; output lifecycle status/close handle, never a broad service port interface copying a class. Remote content sandbox:true, no appData/views protocols, no application RPC; open external links only from validated native events/user actions. Privileged host menu shows active server identity and opens local manager independently of remote connectivity.

Native evidence resolves some uncertainty:
Actual installed SDK source is .cache/hutch/releases/electrobun/2.0.2/macos-arm64/api/sdks/main. BrowserView.ts supports partition/sandbox. proc/native.ts exposes Session.fromPartition(), cookie get/set/remove and clearStorageData. BrowserWindow.ts currently neither accepts nor forwards partition into its default BrowserView (explicit TODO). Passing a made-up partition option to BrowserWindow would silently fail isolation.
Recommended implementation: trusted packaged views:// workspace-container page creates a sandboxed <electrobun-webview> with explicit per-server/device partition; remote child has no RPC. Container/native menu is trusted app content and has only narrowly validated manager operations. Native child events are authenticated by actual view identity, not payload sender claims. Alternative: add upstream BrowserWindow partition pass-through in SDK, pin it and validate platforms. Do not reach into private native internals or globally enable unsafe RPC to avoid this work.
Cookie bootstrap preferred path: native pairs via TLS, stores durable renewal token, requests a short-lived window-session cookie for the authorized device and installs it in the isolated Session partition before navigation. SDK cookie setter lacks an explicit URL field (domain is optional), so host-only/Secure/SameSite correctness must be proven; if uncertain use the same-origin single-use fragment bootstrap which lets the browser set its own cookie with Set-Cookie. An unavailable store can offer an explicitly temporary memory-only connection, but durable device support on advertised platforms remains a release criterion. BrowserWindow declarations alone do not prove WKWebView/WebView2/WebKitGTK behavior.
Fallback when a WebView cannot play a supported file: native manager can open an external browser using a fresh single-use window grant (explicit browser device identity, no durable token in URL), keep catalog/recovery available and explain unsupported embedded playback. This is useful recovery, NOT a replacement for the requested native remote workspace. If a platform cannot isolate remote WebViews, use safe browser opening on that platform until SDK repair; label native v1 support incomplete and fix/limit the published platform matrix openly.

5. SERVER DATA, PROTOCOL AND ENDPOINT SKETCH
Persist via existing Drizzle migrations, never ad hoc schema creation outside migration pipeline:
- server_identity singleton: id, createdAt, protocolMajor, identityEpoch. Clone operation creates a new id/epoch and revokes credentials; restore same server retains ID but can deliberately rotate sessions.
- remote_config: schemaVersion, enabled, listen transport, explicit bind interfaces/addresses, port, canonical origins, trusted proxy peers, TLS certificate references, owned Tailscale config fingerprint, appliedGeneration.
- authorized_devices: id, displayName, kind, role playback/manage/admin, canDeleteFiles, profileId, createdAt, lastSeenAt, revokedAt, grantVersion.
- session_families and session_tokens: deviceId, tokenHash, expiry, renewal lineage, revoked state; never raw bearer secrets.
- pairing_grants: tokenHash, optional short-code hash, role/capabilities, expiresAt, consumedAt, maxAttempts, issuer. Invitation creation and consume go through atomic DB transactions.
- playback_profiles and device_profile_memberships; playback_positions keyed profileId + media stable key (torrent infohash/file identity), revision, position/duration/updatedAt.
- Optional external_media_grants hashed and scoped file/expiry/device, and mutation operation receipts for worker side effects.
Native connection catalog lives in separate local config (atomic file replace or a small native DB) and only stores server IDs, labels, trusted origins, routes, secure-store handles and startup mode. It does not depend on hosting DB lock.

Public minimal /.well-known/tofu: product, serverId, displayName, protocol {major,minClient,maxClient}, appVersion, supported onboarding methods, TLS expectations. No filesystem paths, accounts, routes on other private interfaces or secrets. Keep schema version independent of product version.
Authenticated /api/session: deviceId, displayName, current grants, profileId, authorizationVersion, safe host descriptor, relevant capabilities. A remote caller never gets isLocalHost merely because server runtime is desktop.
Routes (illustrative final naming):
POST /api/connections/invitations; DELETE /.../:id (admin)
POST /api/auth/pair (public, rate-limited, typed 400/401/409/410/429)
POST /api/auth/renew; POST /api/auth/logout; POST /api/auth/window-grants
GET /api/connections/devices; PATCH /.../:id/grants; DELETE /.../:id
GET/PATCH /api/connections/config; POST /.../validate; POST /.../apply
GET /api/playback/profile; GET/PUT /api/playback/positions/:mediaKey
POST /api/player/external-grants; DELETE /.../:id
Keep typed constant plugins and inferred results. A real authorization evaluator may perform token validation, role computation and revocation lookup; a trivial generic wrapper that only calls another endpoint is prohibited. Use route macro/guard support that preserves literal Elysia failure statuses in inferred Eden types; prove 401/403 unions visible, not widened to Response.

Capabilities are concrete facts (canBrowse, canManageTorrents, canDeleteFiles, canAdminister, canUseHostNativeActions, media range support, protocol) distinct from OS and server desktop mode. Admin does not confer the host-native-window capability to a remote browser. Adding devices/grants cannot grant stronger rights than issuer.

6. PAIRING, SESSIONS AND REVOCATION DEFAULTS
Invitations default Playback, 10-minute expiry, single device; QR/link holds at least 128-bit secret in fragment. Manual code uses a high-entropy human-readable code (e.g. 10 base32 chars) with strict per-grant and per-peer attempt limits; do not use unlimited six-digit global lookup. Always verify descriptor/protocol before spending invitation. User chooses browser vs desktop before consumption. Native custom scheme accepts only supported validated structured pairing links; never arbitrary command execution/redirect target.

Atomic consumption creates device, session family and grant consumption in one SQLite transaction. For response-loss safety a bounded redemption retry can use the same client-generated redemption nonce and proof secret to recover the SAME session, never create another device; short-lived sealed result storage or deterministic one-time recovery must be specified/tested. Simpler acceptable behavior is clear 'already used; create a new invitation' recovery, but no silent infinite retry. Review chooses recovery policy.

Remote browser receives host-only __Host-tofu session cookie Secure,HttpOnly,Path=/,SameSite=Strict; renewal credential, if distinct, is HttpOnly too and never localStorage. Native durable renewal token stays in Bun.secrets; short-lived browser cookie may be renewed by trusted host while active. Suggested defaults: 1-hour access, 30-day inactive renewal, 180-day absolute session family, visible expiry. Concurrent tabs/windows need one rotation owner or a bounded previous-token grace/replay design; legitimate simultaneous renewal must not falsely revoke family. Access is DB-checked on every request, not an unrevocable JWT until expiration.

CSRF checks compare actual configured origin against Origin/Referer and browser fetch metadata for cookie mutations. Native credential requests use explicit Authorization and no ambient cookies, never treat absent Origin as a browser exemption. Browser unknown/missing origin mutation fails. Public pairing requires same-origin browser proof OR native explicit bearer exchange contract. Validate Host/canonical origin independent of proxy headers. Reject credentialed cross-origin requests; no wildcard CORS. Return safe public problem messages and redact cookies, Authorization, fragments, codes, access URLs in logs.

Device revocation transaction then process-owned abort registry; multi-process mode is not introduced. Close SSE, bounded media readers, deferred output, worker range waits; reject new requests. Permissions downgrade has same abort semantics. Headless recovery is a local CLI with data-directory/OS-user ownership, using a local Unix socket/named pipe for running instance or exclusive offline DB lease when stopped. No extra HTTP listener and no unauthenticated 'localhost is admin' endpoint. CLI can create fresh admin invitation, revoke sessions, disable sharing and repair TLS configuration.

7. SYNC, MUTATIONS AND CONNECTION OWNERSHIP
Set sync.principal to serverId:deviceId:authorizationVersion for authenticated network mutations. Stable across access-token rotation; changes after grant changes to prevent replay of results under old permissions. Native host actions use a separately identified host process/window principal. Direct in-process library reads do not require mutation principal; explicitly disallow unauthenticated network default 'local'. Current journal is cursor-only global invalidation: retain it so all authorized clients refetch their own endpoints and no private tags/scopes leak. Do not replace it with a device-only change feed that would stop other devices seeing shared library changes.

Sync admission/auth always runs before beginMutation/replay. Browser caches are per loaded origin/window generation, private state additionally per device/grantVersion. Clear private cache and remount on identity change, downgrade/logout, server switch or incompatible reconnect. Never persist admin DTOs in generic durable cache. Shared internal snapshot cache never includes access-dependent response fields.

One connection supervisor per native server entry owns route probing, auth renewal, backoff and reconnect, with scoped resources/reference count for windows. Within each web workspace, one coordinator owns session/state SSE/polling recovery; integrate existing Furin sync owner rather than layering independent retry timers on every component. These are separate transport/lifecycle responsibilities, not competing reconnect owners. Full-jitter bounded backoff, offline/online/wake triggers, generation counter; stale successes from old attempts cannot publish state. Auth/identity/certificate/config/protocol failures are blocked states, not fast retry loops.

Routes are hints. Probe descriptor without credentials, validate TLS and expected ID; learned routes only accepted from authenticated descriptor and canonicalized to HTTPS origins (no userinfo/path/query/fragment). Never downgrade HTTPS, silently switch to localhost, or send a token to an untrusted origin. UUID matching alone cannot authorize a newly advertised origin; TLS plus approved trust/host-issued route association is required. Cookies are origin-bound: native manager issues a fresh window grant for a new approved origin; browser-only cross-origin failover requires deliberate navigation/association and cannot silently carry cookies. Healthy playback stays on its current route; after route failure close old resources, reconnect and resume from last position. A webpage cannot seamlessly retarget its protected client to a different origin.

Do not blindly retry side effects. Existing idempotency may persist response only AFTER torrent-worker effect; a crash between effect and receipt is not exactly-once. For torrent add use canonical infohash and persisted operation ID; pause/resume/set-priority are desired-state commands; destructive remove/move needs durable queued operation receipt and reconciliation. Reserve per-resource queues before first await, pass operation IDs into worker, persist result/status and reconcile at startup. Do not hold SQLite transactions open while waiting for torrent IO. Use revision/If-Match-style optimistic conflict checks for settings/grants and typed 409 when state changed. Client can query operation result after ambiguous timeout. This is a required production behavior, not a claim that Furin's cache alone solves distributed side effects.

8. NETWORK, TLS AND CONFIGURATION LIFECYCLE
Default disabled: original local private access. Enabled LAN: same apiPlugin listener with TLS; explicitly selected interface binding (wildcard means all and must be honestly labeled, not 'LAN only'), stable mDNS service _tofu._tcp with serverId/protocol/port hints only. Prefer stable .local name + SAN and show IP alternative only when certified; handle IPv6 brackets/link-local scope and multi-NIC. Do not promise wildcard local address works through guest Wi-Fi isolation. Port 0 is unsuitable as a remembered public address; select a persistent configured port, detect conflict, never silently shift saved public endpoint.

Local certificate mode: generate and manage per-installation CA/leaf with short renewable leaf lifetime; show CA fingerprint and guided trust installation on each browser device. Protect CA private key, never send it to clients. No disabled TLS validation, global trust injection without explicit UI action, or 'Proceed anyway' claim that playback will be secure-context compatible. Browser DNS/.local support varies; discovery is convenience for native app, URL/manual fallback remains. Certificate expiry and IP changes get repair states and renewal before expiry.

Tailscale mode: integrate supported tailscale CLI/LocalAPI status and HTTPS Serve, own only a specific route/port configuration, never reset somebody else's Serve setup. Tailscale is a transport, not authentication; normal Tofu pairing still required. Feature discovers missing installation/login/HTTPS settings and explains exact action. Tailnet private Serve, never Funnel. TLS-terminating proxy is external infrastructure, not an extra Tofu application listener.

Custom reverse proxy mode: configure canonical HTTPS origin, trusted immediate proxy peers and forwarded-header policy explicitly; honor forwarded origin ONLY from those peers. Do not let clients spoof X-Forwarded-For to bypass rate limits or access controls. Loopback HTTP upstream is allowed only behind trusted local proxy; remote users still HTTPS. Proxies must pass cookies/Range, stream SSE without buffering, preserve isolation headers and support large responses/timeouts. Local and remote paths remain same-origin relative URLs. Prefer separate hostname/origin over arbitrary subpath mounting in v1; if subpath is claimed supported, validate Furin asset/media/auth/cookie paths end-to-end.

Listener changes cannot be made 'atomically seamless' while insisting on one listener. Use validated proposed config + pending/apply journal, explain a short server reconnect, orderly stop/rebind same app or process restart, verify readiness, then mark active. On failure restore prior config/listener; if process crashes pending journal restores last-good at next boot. Do not hold a second live public listener to hide restart. Other services finish initialization before listening; clients see 'Restarting connections' and supervisor resumes. Secrets/cert validation and cheap port availability checks precede commit, but acknowledge unavoidable port race with typed conflict/rollback.

9. MEDIA AND PRODUCT SEMANTICS
Playback role sees all safe library items (no hidden per-folder ACL in v1), streams files and manages own playback profile. Manage additionally adds/pauses/resumes/reorders/settings limited to download operation; actual file deletion requires explicit canDeleteFiles. Admin manages server integrations/connections but remote native-host dialogs remain denied. Removing torrent metadata without deleting content differs clearly from deleting files; apply permission on every destructive side-effect path, including automation settings that could indirectly delete files. Settings/integration/automation configuration should be Admin; do not accidentally let Manage install arbitrary automation that escalates filesystem control.

Range service owns per-device and global admission, bounded buffers, fair queue and cancellation. Starting proposal: at most 4 in-flight reads/device, 16 global, 64 MiB total materialized range budget, 4 MiB chunk cap; benchmark and tune. Excess work returns typed 429 with Retry-After or bounded wait, never unbounded pending promises. Deadline for unavailable pieces; map paused/removed/storage offline/conflict to explicit recoverable problems. Complete no-Range and /content responses also use cancellable chunked streams under session registry; no unabortable sendfile shortcut. HEAD validates grant but starts no torrent wait; Range grammar rejects invalid/multi-range unless deliberately implemented, honors suffix and 416 Content-Range. Preserve exact bytes and no middleware file-slice regression in packaged Bun. File metadata queries must not disclose full path.

Playback progression persisted periodically and on pause/end/pagehide best effort, revisioned profile scoped. Default profile per device; explicit host-granted shared profile is optional join action, not arbitrary caller-supplied profileId. Concurrent position updates must distinguish explicit seek backwards from stale update: playback session/generation + sequence and compare revision, not max(position) which breaks rewinds. Audio/subtitle preferences per device/profile; media IDs survive ordinary server restart.

External player: issue short-lived revocable capability limited to one file/read scope, support Range requests for its lifetime, no general session. External player cannot normally send browser cookie; a signed/opaque URL may carry this limited secret, therefore scrub URL query logs/referrer/history and warn its holder can read that file until expiry. User-chosen expiry must cover playback/seek; do not make a one-use token that fails the second Range. Local native 'Open in VLC' opens on viewing device; host-local reveal/open remains only local-window authority. Browser gets copy/open stream link where appropriate.

Host-native actions: logs/folder reveal, directory picker, associations, desktop background/update install, local openings are accessible only to attested local host window/native manager, NEVER because runtime.kind==='desktop'. Remote administrators can type validated host paths for settings but cannot invoke surprise dialogs on host. Native client downloads/openings must explicitly select destination server; do not import another host's local filesystem paths. Client update and host update displayed separately.

AniList: existing owner credentials remain host-owned and Admin-only. Guest progress never mutates owner AniList. Remote OAuth requires provider-supported registered redirect origin or a local-owner completion flow; do not simply change redirect_uri to arbitrary LAN HTTPS expecting provider acceptance. Host admin can begin authorization, complete provider flow on owner local host or approved callback endpoint, poll result remotely with initiating-device/state binding and cancellation. If current provider app only supports existing callback, ship remote admin guidance to complete on host; full direct remote OAuth requires registered provider configuration and explicit compatibility proof. Catalog browsing may use safe shared reads; account details/token/editor mutation privileged.

10. IMPLEMENTATION SEQUENCE AND ACCEPTANCE
Use vertical integration slices, not all-tests-first. Furin AGENTS requires TDD skill; it has been read. Current user already approved overall scope and requested review, so no redundant generic approval step; actual implementation waits for new UI gate. Tests in framework repository may test framework behavior; Tofu only essential integration cases via typed Eden/real services/real peers.

Gate: no src/lib/client.ts edits, no second application listener, trusted route match policy enforced for HTML and data/defer, packaged crossOriginIsolated/VLC works. ADDENDUM — OPERATION MATRIX AND HOST FILE BOUNDARY (aligned for UI review)
Playback: safe library/search/detail reads; GET/HEAD/Range/download of torrent-owned media; own profile progress/preferences; own logout; own permitted external-media link. No peers/tracker credentials, raw host paths, account tokens or arbitrary content URL/path.
Manage: Playback plus add by magnet/torrent upload to an EXISTING admin-approved destination ID, pause/resume/prioritize/reorder/remove torrent metadata. No creation/editing of filesystem destinations, arbitrary save path/locate/relink/move path, settings that enable watches/delete-on-add, plugins/provider configuration, shell/native actions or editable automation rules. Moving between existing approved destinations may be allowed if implementation validates both roots and destructive overwrite policies; otherwise keep Admin. Pausing an already approved automation is a separate optional capability, not implied permission to edit its definition. Default v1: automation administration is Admin.
Admin: account/integration/automation/server settings; create/edit approved destination roots; access devices/configuration; server lifecycle where supported. Admin still needs explicit delete-files capability for deleting content, and cannot obtain local-host-native-window authority through remote HTTP. Permission changes cannot exceed issuer's effective authority; local recovery owner is the ultimate grant authority.
Delete-files: required for every path that physically removes/overwrites media, not only the obvious DELETE endpoint. Audit torrent removal, move conflicts, watched file deletion, cleanup automation and destination removal. Admin configuring destructive automation needs this permission or must explicitly disable destructive behavior.

Server controls filesystem access through trusted destination IDs and torrent/file IDs. Network requests never provide an arbitrary path to stream/read/download. Uploaded torrent metadata can contain traversal names: normalize validated file identities, canonicalize real paths and reject escape outside configured destination roots, including symlink swaps and platform separators. Prefer descriptor/open-file semantics with post-open checks where filesystem permits; do not trust a lexical startsWith(root) check. Existing trusted host configuration is not proof that a remote manager may read unrelated files already present in that root. Only content belonging to the selected indexed torrent/file identity is readable; validate expected path/identity at serving time and handle replacement/removal safely. A raw host path must never be inferred from an arbitrary Range filename suffix. Redact filesystem paths in viewer-facing failures and SSE payloads.

Opus must reconcile UI labels against this exact matrix. In particular 'manage destinations/automation' is too broad unless explicitly narrowed to approved resources and immutable definitions. This is server enforcement, not hiding controls.
