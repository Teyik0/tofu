1. PRODUCT CONTRACT AND VISUAL DIRECTION

An installation can host its own library, connect to several other Tofu hosts, or run as a client without a torrent engine. A browser visits one server origin. A desktop shell owns the saved-server catalog and opens a server's own same-origin web interface in an unprivileged, isolated window. No universal client that rewrites Eden's origin, and no changes to src/lib/client.ts.

Preserve Tofu's current calm, compact utility UI: olive semantic accents, warm neutral backgrounds, existing system typography, Lucide icons, Base UI/shadcn components. This is an extension, not a redesign. Respect existing 190px library sidebar, 230px settings navigation, grouped Field rows with 14px containers, 960px maximum settings content. src/styles.css:324 defines light colors, :414 dark colors, :4375 settings layout. Use existing semantic colors and focus treatment. The frontend-design skill's general encouragement to invent a new font does not override this product's established design.

Product vocabulary: Server = machine and library; Device = authorized client session; Address = one route to a server; Playback profile = progress namespace. A server has an administrator-controlled name and a local-only optional alias in the desktop catalog. Never conflate address, identity, session, and profile.

3. INFORMATION ARCHITECTURE / OWNERSHIP

A. Trusted desktop 'Servers' manager, available from application menu/tray even with no local server or a failed remote page. It owns the picker, catalog, addresses, local-only aliases, native credentials, client-only setting, and app updates. This surface is bundled/local and does not depend on root.tsx's library loader or a second HTTP listener. Native title/menu identifies the actual selected host; remote document titles are not authoritative.

B. Server workspace at its own origin. Sidebar header gains a compact server identity row: name, 'This computer' or server designation where genuinely known, connection state, access label in details. Browser does not list other servers' secrets. In desktop, a native menu/toolbar action opens the trusted manager. Do not give the remote DOM access to a generic native bridge to render a privileged picker. A narrow user-triggered deep link to the manager may be provided if origin/navigation validation is proven; native menu remains sufficient fallback.

C. Host administration at /options/connections. Heading 'Settings / Connections' and persistent context 'Server: Home Mac'. Sections: Network access, Addresses, Pair another device, Authorized devices. This always configures the currently displayed server, not the client running the window. Admin-only host controls; other roles get 'Your connection' with own access, profile, and sign out.

D. Public minimal /pair and signed-out/revoked pages, not nested under the protected full-dashboard root. Show no library names/files before authentication. Exact route separation depends on framework solution.

4. TRUSTED DESKTOP SERVERS MANAGER

Rows: machine icon; local alias/host name; 'This computer' or safe hostname; text status; current checkmark; overflow actions. Local row stays visible as 'Server off' in client-only mode. Known addresses are in Details, never duplicated as separate server rows. Server ID deduplicates verified identities; identical display names remain distinct with host/address details.

Primary actions: Open, Add server. Overflow: Open in new window, Rename on this device, Connection details, Disconnect, Forget server. Disconnect keeps pairing/catalog; Forget removes local credentials/cache and attempts session revocation. If offline, state 'Removed here. Its session could not be revoked; revoke it on the server.' Do not claim revocation succeeded. Neither action stops a remote torrent engine.

Native picker mirrors this catalog with current server, state, Add server and Manage servers. Opening a different server should use a distinct window by default when the current window is playing, preventing accidental interruption. Otherwise selecting switches the native-owned window context after cleanup; unsaved forms prompt discard/keep. Server ID scopes all caches and stored routes; URL equality is not identity.

Boot: load trusted shell/catalog first; local mode initializes required services before opening its workspace. Client-only boot never imports/initializes local DB/torrent services. Prefer last selected saved server, but offline/auth/cert failure keeps the manager usable. Do not silently fall back to 'This computer' under the remote name. First launch with no local server shows 'Connect to a server' plus 'Start a server on this computer'.

Local server setting: 'Run a server on this computer'. Turning off explains local downloads, automation and remote playback stop; files and saved connections remain. Show active transfers/streams count when available. Commit valid setting and restart only on explicit 'Restart and turn off'. Changing this in the manager affects this device, never the currently viewed remote host. On relaunch failure expose recovery and re-enable rather than a blank window.

5. ADD SERVER AND DISCOVERY

Dialog with two routes: paste invitation link (primary) or enter HTTPS address and pairing code. Full link populates fields; validate scheme/userinfo/fragment/redirect rules before navigation. Nearby servers is a secondary expandable list after the user requests discovery; show discovery permission denied, scanning, none found and multiple interfaces distinctly. No continuous unrequested probe that triggers platform privacy prompts. Name/address advertised by discovery is untrusted metadata until TLS and identity verification; do not send credentials to it blindly.

Steps: Address -> Verify connection -> Pair -> Open. Show contacted HTTPS hostname, resolved server name, effective role, and friendly device label (editable). A connection check distinguishes not reachable, certificate not trusted, identity changed, pairing expired/used, not allowed, and version unsupported. Address-only without code gives instructions to create an invitation on the host; never invent an unsolicited approval request protocol.

After success, save verified stable server ID and usable route, discard invitation secret, store native session in OS-protected storage, open the same-origin remote page with properly isolated cookies. If already saved, offer 'Open existing connection' or add verified route; do not overwrite another server's credentials because names match.

6. HOST NETWORK ACCESS / HTTPS

The sharing toggle is not an optimistic success indicator. Disabled state says 'Only this computer can connect'. Enable opens setup, keeps prior valid configuration until all required checks pass. Setup choice: 'Local network', 'Tailscale', 'Custom HTTPS'. Explicit Apply / Save and apply is required for connectivity changes; automatic on-blur saving is inappropriate here. Show which addresses will change and whether connections/restart are affected before commit. If acting remotely on the sole available route, require a tested replacement or clear recovery instructions plus architecture-approved rollback mechanism.

Local network: server name, listening port, selected interface or appropriately described binding, generated local certificate / provided certificate choice, certificate fingerprint and expiry in details. Explain directly: 'Install this server’s certificate authority on each device before opening Tofu in a browser.' Show platform-specific trust steps, authentic fingerprint verification, download from the already authenticated host setup surface, and 'Check again'. Never offer a global disable-certificate-validation switch or imply clicking through browser warnings establishes a valid secure context. Desktop pinning, if supported, is a separate architecture decision; do not promise OS webview support without a proof. Plain HTTP remote playback is not a supported success state.

Tailscale: prerequisite state machine Not checked -> Not installed / Signed out / HTTPS not enabled / Configuration conflict / Ready. Show 'Check Tailscale' then setup action, concrete safe explanation of private tailnet requirement, actual HTTPS address, and effect of disabling only Tofu-owned configuration. Do not turn on Funnel/public exposure. Server-side checks do not prove a phone is on the tailnet or can reach the address. No fake green global 'Secure everywhere' status.

Custom HTTPS: administrator-provided HTTPS origin, certificate configuration or external proxy mode, checks for current host identity, supported streaming/range requests, secure context and isolation headers. Explain playback compatibility failures separately from valid TLS. Keys are never returned to UI. Paths and proxy configuration remain advanced fields. If external proxy is unmanaged, disabling Tofu's local-LAN binding does not necessarily disable it: display exposure per route, with an honest overall summary.

Addresses: name (Local network/Tailscale/Custom), URL, current route badge, observed check state and time, copy action, details. Exclude loopback and unavailable routes from share QR choices. Multi-address server may show IPv4/IPv6 separately within details. An advertised address reads 'Not verified on other devices' until there is evidence. mDNS availability is best effort; keep manual address entry. Updates/expiry warn in advance while retaining working connections.

7. PAIRING / ROLES / AUTHORIZED DEVICES

Create invitation is admin-authorized. Fields: label, role, optional playback profile binding, expiry (propose 10 minutes default), separate 'Allow deleting downloaded files' for Management. Default Playback. Role definitions:
- Playback: browse allowed library, stream, update own/assigned profile progress and own UI preferences. No torrent/library mutation, automation or owner AniList mutation.
- Management: Playback plus add/pause/resume/reorder/remove torrent entries using existing administrator-approved destination IDs. No arbitrary host paths, destination configuration, automation configuration, integration settings or credential access; follow architecture's explicit operation matrix. Removing an entry without deleting files must be a separate clearly named operation. No credential/network/device administration.
- Administration: host settings, integrations and device permissions. Architecture requires an explicit delete-files grant even for administrators and bounded delegation. UI must show whether delete-files is granted and must not imply a delegated administrator can self-escalate it. REVIEW DECISION: define an owner/local recovery authority above bounded remote Administration, or redesign role semantics so the permission editor cannot grant rights the session does not already hold.
Delete-files is displayed explicitly in grant summary and destructive confirmation. New lower-privilege invitations cannot grant more than creator's authority. Permission changes take effect live; an open form receives a useful 403 explanation instead of silently failing.

Invitation result: endpoint selector; QR (real generated code in production); copy link; copy code for manual desktop entry; absolute expiry with relative countdown; Revoke invitation. Raw invitation is shown only at creation, not reread from hashed storage. Closing the dialog retains metadata but cannot reveal the original secret again: generate a replacement. Used/expired/revoked links remain auditable metadata if retained, with disabled copy/reuse. QR alternate accessible text is label + readable address, not hidden secret duplication.

QR goes to an HTTPS /pair link with credential in fragment. Minimal page reads it once, removes it from history, retains it only in memory (amended: see specification.md, session storage restores it on reload for at most 15 minutes). Offer 'Continue in browser' and explicit 'Open in Tofu' before atomic consumption. The browser must not automatically spend the token before desktop handoff. Choosing desktop hands a short-lived invitation to the allowlisted app protocol (tofu or tofu-dev), never a durable bearer. User can paste a fresh link if app launch fails after consumption. Avoid third-party resources/analytics on this page. Display server/address and intended grant; let device label be edited before Continue.

Authorized devices rows: user-chosen label (not trusted proof), client type, effective role/grants, last active timestamp, session expiry, active streams count, 'This session' marker. Detail drawer: rename session, change grants/profile, revoke. Revoke confirmation names host and device and states playback stops immediately. The initiating UI updates from the confirmed server result; an offline request is not marked successful. 'Revoke all other devices' protects current admin by default. Explicit 'Revoke all remote access' also revokes invitations/current remote sessions and explains local recovery. Non-admin sees only own session and can sign out.

8. CONNECTION / PLAYBACK STATES

One shared connection driver owns retries. Views subscribe; no timer per component. Current src/components/tofu-state-sync.tsx:51 ignores typed API errors and reconnects every second, so it must be replaced with explicit transport/auth/version classification.

Connected: quiet status, route and grant in details. Connecting/Reconnecting: small textual banner, attempt/retry action, preserve last in-memory library as 'Last updated ...'; no stale mutation controls. Browser offline is a hint, not proof the host is down. After reconnect fetch a fresh snapshot; do not replay destructive mutations blindly. Auth expired: refresh once through contract; revoked: stop retries, clear private caches, pause/destroy player and show 'Access to Home Mac was removed. Ask its owner for a new invitation'. Certificate/identity change: stop credentials, dedicated error with hostname and recovery. Incompatible: identify which desktop/server needs update and allow manager/back navigation; never update automatically or fake compatibility. Busy/stream limit: show retry timing; not network failure.

Player keeps existing controls and source-relative media URL. Add host identity to visible header and connection details; hide controls during cinema mode as currently but keep accessible name. States distinguish initial loading, waiting for torrent pieces, network reconnect, audio gesture required, paused incomplete torrent, storage unavailable, deleted file, no permission, server capacity, unsupported secure context/decoder. Playback user cannot be told to click a Resume button they do not possess: say 'This download is paused on Home Mac. Ask someone with Management access to resume it'. Management can resume through the explicit authorized endpoint.

On transient failure preserve current time, track choice and playing/paused intent; reconnect and seek to last confirmed position. Route failover must not reset progress or spontaneously restart a user-paused video. Avoid switching from a healthy playback route just because a lower-latency route appears. Seeking cancels obsolete reads. Multiple simultaneous playback sessions show server limits without revealing other viewers' private activity to Playback role. Browser close does not stop server downloads. Turning sharing off closes only affected remote routes per actual configuration.

External player: current media-player.tsx:435 calls host 'open' and is unsafe for a remote user. Local native context may 'Open with system player on this computer'. Remote/browser gets 'Copy temporary playback link' if capability exists, TTL and revoke behavior visible. Native manager may launch client-side player only through a specific user action and constrained IPC. It must never open the host's player on behalf of a guest. No permanent media URL carrying general session secret.

9. PREFERENCES / ANILIST / NATIVE ACTIONS

Server scoped: files, destinations, transfers, bandwidth, automation, provider credentials, server sharing, server update lifecycle. Each panel says 'Applies to Home Mac' and any confirmation repeats it. Read-only clients never get secret paths/provider tokens in SSR payloads just because controls are hidden.

Device scoped: appearance, sidebar state, volume, audio/subtitle defaults, local alias, preferred route, desktop start/local server options, app updates. New device defaults can migrate from existing global theme but changing it must not broadcast to all viewers. In browser these preferences are local to that browser/origin unless explicitly profile-shared. In desktop the shell owns its preferences; web page appearance can remain origin-local with explicit labeling. Do not invent cross-origin preference forwarding to Eden.

Progress: server ID + playback profile + media/file identity. New paired device gets private profile by default; admin may bind it to an existing profile while associating or from session details. Explain joining an existing profile shares playback history; do not reveal profile list to unpaired guests. Keep ordinary preferences separate from profile progress. Concurrent progress writes need architecture-defined revision policy, not blind 'largest timestamp wins' if a user rewatches. Offline updates must not leak into another profile/server.

AniList: existing account stays server-owned. Playback progress never automatically edits owner's AniList. Explicit authorized 'Update AniList account <name> on Home Mac' action only with grant. Guests do not receive account secrets or private list/diagnostic data without permission. Separate public catalog browsing from owner's personalized data. OAuth opened on consulting device; remote admin can complete a validated pending flow on same origin or paste callback URL if provider redirect contract requires; no localhost callback assumption, no host browser launched for a remote viewer. Multi-user AniList accounts is not silently added to v1.

Native-only controls (folder dialog, reveal file, .torrent default app, background, host updater, logs) depend on verified local window capabilities, not dashboard.session.mode. Existing src/pages/options/index.tsx:45, downloads.tsx:103, detail.tsx:168 and root.tsx:65 use host mode and must be audited. A remote admin enters a server filesystem path if supported, clearly labeled host-side; clicking Browse must never pick a folder on the wrong computer. OS-opened magnets/torrents in client-only mode need a trusted target picker with destination/grant check and no automatic upload to last remote server.

12. RELEASE ACCEPTANCE (UI AND OBSERVABLE CONTRACT)

1) A fresh upgrade keeps sharing off and existing local library behavior; no network disclosure before opt-in.
2) Native manager starts in client-only mode with no local torrent/database initialization; offline remote has Retry/Edit address/Choose another server and manager remains usable.
3) Browser and desktop associate exactly once; expired/used tokens produce actionable errors, never duplicate sessions; browser-to-desktop choice does not consume token twice.
4) Two addresses for same verified server give one catalog row; two same-name servers remain distinct; identity change never leaks old credentials.
5) Host context appears in Settings, destructive dialogs and player; changing remote bandwidth cannot mutate local host; appearance on one client cannot unexpectedly change others.
6) Playback user can browse/play/own progress but has no operational menus; direct forbidden routes/mutations return typed denial; SSR/data/live payloads omit private host data.
7) Management without delete-files can remove torrent entry keeping data, cannot delete bytes via UI or API. Administration effects shown explicitly.
8) Revocation during stream closes access and stops retry; session row confirms actual success; offline revoke displays failure.
9) LAN certificate onboarding explains platform trust; untrusted certificate never shows Connected/Ready-to-play. Tailscale unprobed state differs from unavailable; QR never encodes localhost for another device.
10) Read-only viewer of paused incomplete file sees correct action; reconnect retains playhead/tracks/intent, duplicate mutation never follows a network retry.
11) Own progress is isolated across devices/profiles unless deliberately shared; guest playback does not alter owner AniList.
12) Remote content cannot open host or client native file dialogs/players through a broad bridge; local system-opened .torrent in client-only mode gets explicit target selection.
13) Screen reader/keyboard can pair, switch, inspect grants and revoke; 320px/200% zoom has usable navigation and no clipped primary actions.
14) Disabling hosting explains affected downloads/streams; disabling one exposure route does not claim unmanaged proxy routes are closed. Restart/recovery returns to correct host.
15) Real HTTPS two-process + real torrent peers integration validates essential boundaries. Follow repo policy: no component snapshots/framework-internal tests; use focused manual/browser acceptance and essential API integration tests.

13. COORDINATION / NON-GOALS

Architecture must prove before UI integration: public vs protected root rendering with direct Eden; role-safe common SSR and request-specific own data; exact capability/permission matrix; trusted shell with no extra listener, secure cookie partitions and token handoff; local certificate trust in shipped webviews; profile/progress persistence and concurrency; exposure apply/rollback and native-window ownership. Do not cover a missing contract with optimistic mock behavior.

Complete v1 includes browser access, desktop multi-server catalog, client-only boot, headless host, HTTPS LAN/Tailscale/custom setup, discovery where supported, invitations/sessions/roles, reconnect and streaming (including in-progress torrents). Explicit non-goals: Tofu cloud relay/account service, automatic SSH provisioning, transcoding, Cast/TV apps, global merged cross-server library, multi-user AniList account service. Manual SSH tunneling may transport an existing host but has no automatic setup wizard in v1.

ARCHITECTURE COORDINATION ADDENDUM
The agreed SSR direction is an invariant viewer-safe dashboard DTO with no session-specific hydration, settings, secrets, filesystem paths, peer metadata or native availability. Fetch /api/session capabilities and own progress in the browser after mount through existing Eden. Show a skeleton until that completes and never briefly render admin/native controls. Admin settings SSR may exist only under a route subtree authenticated before every document/data/defer loader. Default SSR appearance is neutral, then device/origin-scoped preference applies. Trusted packaged views:// container can own a sandboxed, partitioned Electrobun BrowserView: native server picker stays outside remote webview. BrowserWindow does not forward partition. Secret-store failure needs explicit temporary connection mode or retry, not plaintext fallback. These are proof-gated architecture directions, not claims of finished runtime support.
