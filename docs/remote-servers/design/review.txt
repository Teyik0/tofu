0. VERDICT
=====================================================================
APPROVE WITH REQUIRED CHANGES. The two proposals are serious, mostly consistent and correctly refuse the dangerous shortcuts
(no client.ts edit, no ALS/cookie forwarding, no second app listener, no universal SPA, honest TLS). They are NOT yet
implementation-ready: source verification found five hard blockers the artifacts either miss or get wrong, and one large
framework change that should be removed rather than built.

Hard blockers (must be reflected in the implementation brief before code starts):
  H1  LAN-direct HTTPS on the single listener moves the HOST'S OWN desktop window to HTTPS; the pinned SDK has no TLS trust hook
      and the existing HTTP bootstrap cookie flow breaks under schemeful same-site. Unaddressed in both artifacts.
  H2  Remote Administration is currently equivalent to arbitrary file write as the host OS user (arbitrary destination roots +
      torrent-controlled file names + host-opening endpoints). "Admin without delete-files" is meaningless until bounded.
  H3  Putting grantVersion in the sync principal converts legitimate retries into re-executed side effects after a grant change.
  H4  Any public Furin page (pairing, signed-out, anonymous 404/error) runs the single root loader and would hydrate the library
      to anonymous visitors. Public surfaces must not be Furin pages.
  H5  Cookies ignore ports: two Tofu servers on one hostname (NAS with two instances, 127.0.0.1 SSH tunnels, same LAN IP) overwrite
      each other's "__Host-tofu" cookie. Cookie name must be server-scoped.

Required simplification (replaces the riskiest P0 framework work):
  S1  Drop the proposed Furin authorizePage(routeId) hook. Make every Furin loader viewer-invariant at the Playback floor and make
      privileged API endpoints reject in-process dispatch. One authentication gate in the existing network dispatch wrapper then
      covers documents, /_furin/data, deferred frames, 404/error roots and hydration with no route-policy table to drift.

Everything else below is a refinement or a proof gate. Scope of v1 is NOT reduced; two items get honest platform-bounded
acceptance (AniList remote completion, LAN-direct on Linux desktop hosts) with explicit wording instead of silent omission.

2. PRIORITIZED FINDINGS
=====================================================================

--- H1 (BLOCKER) LAN-direct HTTPS breaks the host's own window; no TLS trust API -----------------------------------
Facts: one Bun.serve cannot speak HTTP and HTTPS on one port; V1 makes a second app listener impossible; V6 shows no way for
a webview to accept a private CA except OS trust. In LAN-direct mode the sole listener terminates TLS, so the host's local
window must load https://127.0.0.1:<port> (or localhost). Then: (a) the host OS must trust the installation CA
(macOS keychain trust prompt, Windows Root-store prompt, Linux system store requiring root and WebKitGTK/GnuTLS specifics);
(b) the existing bootstrap 303 from http://127.0.0.1:X to https://127.0.0.1:Y is cross-site under schemeful same-site
(Chromium/WebView2), so the SameSite=Strict cookie is not sent on that navigation and the guard's "same-site" bootstrap
check (runtime.ts:55-64) fails. architecture.txt §4 only says "Prefer HTTPS even for local workspace"; it is mandatory and
its consequences are unplanned. Also, desktop CLIENTS connecting to a LAN-direct host cannot pin the host CA (no SDK hook):
they need OS trust exactly like browsers. ui.txt §6 leaves "desktop pinning" open — resolved: not available in v1.
Required:
  1. Tailscale and Custom-proxy transports keep Tofu's listener on loopback HTTP (Serve/proxy terminate TLS and forward to
     http://127.0.0.1:<stable port>). They need NO host CA trust, NO bootstrap change, NO listener rebind. Make Tailscale the
     recommended transport in the UI (prototype already leads with it).
  2. LAN-direct mode = TLS on the single listener bound to the chosen interface(s) INCLUDING loopback; leaf SAN covers the
     .local name, selected IPs, 127.0.0.1, ::1 and localhost. Enabling LAN-direct on a desktop host includes an explicit
     "Trust on this computer" step (the same guided CA install shown for other devices). Validation refuses to activate
     LAN-direct until the host's own webview handshake succeeds (probe from the native process through the same trust store).
  3. In TLS mode the local window gets its desktop cookie by native Session.fromPartition(localPartition).cookies.set(...)
     before navigation (no listener, no public endpoint). Proof gate G3 must show host-only/Secure/SameSite semantics on all
     three webviews. Only if that fails: TLS bootstrap on the same certificate as an explicitly approved framework exception
     (see §8 user decision U1). HTTP mode keeps today's bootstrap unchanged.
  4. Sharing requires a persisted, configured port (default 3030, conflict detection, never silently changed); runtime.ts:328's
     forced port 0 becomes a host listen configuration input. Tailscale Serve config references this port.
  5. Linux desktop host + LAN-direct is published as "requires administrator trust installation"; if WebKitGTK proof fails,
     LAN-direct is offered on Linux only for headless hosts, and the matrix says so.

--- H2 (BLOCKER) Remote Administration is unbounded host file write -----------------------------------------------
Facts: Admin can create/edit destination roots at arbitrary host paths (architecture addendum: "create/edit approved
destination roots"); any Manage+ device can add a torrent whose metainfo chooses file names; a torrent landing in
~/Library/LaunchAgents or over existing files is code execution or silent destruction as the Tofu OS user. Watched folders
(watched_files table) and custom certificate/key file paths are further host-path inputs. V8 shows host-native side effects
from a remote request. The delete-files capability is therefore theater for Admin today.
Required:
  1. Introduce HOST STORAGE ROOTS: a host-local-only list (editable only from the local window with local-window authority or
     the recovery CLI). Remote Admin can create/rename destinations only beneath a storage root, chosen by root ID + relative
     subpath, canonicalized with realpath and symlink checks at creation and at every write/open. Arbitrary absolute host
     paths, watched-folder paths, certificate/key paths and proxy trust lists are local-authority-only settings.
  2. Torrent add/move never overwrites or verifies-into files not owned by an indexed torrent record: on name collision with a
     foreign file, refuse with typed 409 (or write into a fresh subfolder) — applies to Manage and Admin. This closes the
     "delete by overwrite" path the addendum only mentions for moves.
  3. Every route that triggers host OS behavior (/plugins/:id/credentials/open, desktop module reveal/open/pickers, external
     player open, update install, notifications) requires local-window authority, never runtime.kind. Remote callers receive the
     URL/data to act on their own device.
  4. With 1-3 in place, Admin-without-delete-files is a real boundary; keep it.

--- H3 (BLOCKER) grantVersion inside the sync principal ---------------------------------------------------------------
architecture.txt §7 sets principal = serverId:deviceId:authorizationVersion. Idempotency keys are scoped by principal, so a
client that retries an ambiguous mutation (same Idempotency-Key) after any grant change (even an UPGRADE, or a profile change
that bumps the version) misses the reservation and executes the side effect twice — exactly the duplicate the brief forbids.
The stated motivation (prevent replay under old permissions) is already met by V4: replay happens after route guards.
Required: principal = "device:<deviceId>" for authenticated network requests; "local-window" for local-window authority;
"shared" for in-process dispatch (non-empty, V5). Browser private caches are reset on authorizationVersion change from
/api/session, not through the principal. Never return the unauthenticated default "local".

--- H4 (BLOCKER) Public pages under the single Furin root leak the library ---------------------------------------------
Furin has one root route; root.tsx's loader runs for every document and /_furin/data request including not-found and error
rendering. Under the planned design in-process Eden returns the viewer-safe dashboard WITHOUT knowing who asked, so a
public /pair page, a signed-out page or an anonymous 404 would hydrate the safe library DTO to anyone who can reach the port.
ui.txt §3D defers this to "framework solution"; architecture §3.2 relies on route-policy evaluation.
Required: there are NO public Furin pages. The network admission gate (S1) rejects every unauthenticated request except an
exact allowlist: GET /.well-known/tofu, GET /pair, GET /signed-out, POST /api/auth/pair, the minimal static assets those two
documents need, and local-window bootstrap mechanics. /pair and /signed-out are served by a const Elysia plugin as small
self-contained documents (bundled script emitted at build, strict CSP with hash, no third-party resources, Referrer-Policy
no-referrer, Cache-Control no-store). Unauthenticated document navigations to any other path get a 302 to /signed-out;
unauthenticated data/API/SSE/media get typed 401 problem bodies with no root rendering.

--- H5 (HIGH) Cookie collisions across ports ---------------------------------------------------------------------------
Cookies are scoped by host, not port. "__Host-tofu" set by https://nas.local:3030 is sent to and overwritten by
https://nas.local:3031; with SSH-tunnel routes several servers share 127.0.0.1. Required: browser session cookie name
"__Host-tofu-<first 16 hex of serverId>"; server reads only its own name; logout clears only its own; the identity check on
/api/session also verifies serverId so a mismatched cookie never authenticates against another server's database (it would
fail the hash lookup anyway, but the UX must not loop). Native remote windows remain isolated by partition (serverId+deviceId).

--- S1 (REQUIRED SIMPLIFICATION) Replace route-level page authorization with viewer-invariant SSR ----------------------
architecture.txt §3.1-B/§3.2 adds a framework authorizePage(context, resolved) hook that must fire after matching and before
root/parent/leaf loaders, ISR/cache reads, deferred creation and not-found/error roots, for both document and data transports,
and must carry the original request. That is the single riskiest P0 item (several Furin dispatch paths, AOT/JIT parity, drift
between a routeId policy table and real routes). It is unnecessary:
  - Invariant A: every Furin loader may only call endpoints whose in-process response is allowed for the LOWEST authenticated
    role (Playback). Root loader -> safe dashboard DTO; detail/player loaders -> safe DTOs.
  - Invariant B: privileged API endpoints (settings, instance, automation, devices, connections config, AniList account/editor,
    destinations admin, logs/diagnostics) REJECT in-process dispatch with a typed 403. A loader that accidentally calls one fails
    for everyone at SSR time and is caught immediately by the essential leak test — fail-closed by construction.
  - Privileged panels (options/index instance block, plugins/_route, options/preferences automation, AniList account) fetch in
    the browser through the unchanged shared client after /api/session confirms capability. These are the only three loader
    reads to move (V9).
  - In-process dispatch is READ-ONLY: any non-GET/HEAD in-process request is rejected. Tofu has no server actions that need it.
With A+B, the only framework change for authorization is a dispatch-kind marker plus one admission gate in the existing
desktopApp wrapper (which already sees every listener request with its Server argument). It covers documents, /_furin/data,
deferred frames, 404/error roots and __furinQueries automatically, because whatever they contain is Playback-safe and the
viewer is authenticated. Page "access denied" for lower roles becomes a client-rendered state on the page shell.
Keep from the architecture: private,no-store on every authenticated response; disable ISR/SSG/PPR for Tofu pages; safe DTO
projections (explicit allowlist processing, not spreading); in-flight abort registry.
Framework surface that remains (furin-electrobun, small and testable):
  dispatchKind(request): "network" | "in-process" exported from a framework WeakSet populated in the wrapper before next().
  admission hook option on desktopApp: (request, {peerAddress, server}) => undefined | Response, run for network dispatch only,
  BEFORE the 503 availability check's next() and before Furin/Elysia routing; replaces the hard restrictWebToLoopback rejection
  when sharing is enabled. Requests created later by frameworks (Furin synthetic data request) inherit nothing — and need
  nothing, because admission already happened on the original network request.
Furin core change still recommended but NOT a blocker: pass ctx.request.signal into the synthetic data Request (V3) so client
disconnect cancels deferred work. Server-initiated revocation of an in-flight SSR/deferred response is not required for
confidentiality under Invariant A (the content is Playback-safe and the device was authorized when the request started);
long-lived streams (SSE, media, range waits) MUST abort on revocation — those are Tofu-owned and can be.

--- R1 (HIGH) Local-window authority must not depend on loopback peer or Host --------------------------------------------
With Tailscale Serve or a local reverse proxy, remote requests arrive from 127.0.0.1. With LAN-direct on 0.0.0.0, Host:127.0.0.1
is attacker-controlled. Local-window authority = constant-time match of the in-memory desktop cookie secret (as today) AND
dispatchKind network AND (peer address loopback AND Host loopback) as defense-in-depth. Neither peer nor Host alone ever grants
anything. The desktop cookie is installed only into the local window's partition. Remote "Admin" never obtains it.
Keep the existing loopback bootstrap listener in HTTP mode: it is a framework-internal cookie-setting endpoint that serves no
application route, binds loopback only, and is LESS exposed than the proposed /connect/local#grant redemption route, which
would live on the same listener that is now reachable from the LAN/tailnet. AGENTS.md forbids adding a listener for application
or client transport; it does not require deleting this pre-existing mechanism. Removing it is an optional cleanup once G3
proves native cookie installation everywhere, not v1 work. Reject the architecture's same-listener public bootstrap route.

--- R2 (HIGH) Remote exposure changes: confirm-or-revert, not "tested replacement" ---------------------------------------
Only LAN-direct changes (enable/disable, port, interfaces, certificate) rebind the listener; Tailscale/proxy changes do not (H1).
Rebind = orderly backend stop + start through the host's existing restart path (native-restart.ts) for desktop hosts, and
in-process app.stop(true) + listen for headless only if gate G9 proves Elysia re-listen on the same instance with the guard
intact; otherwise headless requires a supervisor (documented exit code). Apply protocol: persist pending config with a journal,
restart, mark "pending confirmation"; the initiating client must call POST /api/connections/config/confirm through the NEW
active route within 90 s, else the server restores last-good and restarts again; boot with a pending entry and no confirmation
restores last-good. Local-window applies auto-confirm after readiness. No second public listener, no zero-downtime claim.

--- R3 (HIGH) Rate limiting behind proxies ---------------------------------------------------------------------------------
Behind Serve/proxy every peer is loopback, so per-peer limits either lock everyone out or (if keyed on XFF) are spoofable by
local processes. Primary limits are per pairing grant (max 5 failed code attempts, then the grant is burned) and per short
code namespace (global token bucket on failed code lookups, e.g. 30/min with exponential back-off); per-peer limits use the
forwarded client address ONLY when the immediate peer is a configured trusted proxy. Codes: 10 Crockford base32 characters
(50 bits) with per-grant burn is sufficient; QR/link secret 128-bit.

--- R4 (MEDIUM) Session model is more complex than needed -----------------------------------------------------------------
Drop access/refresh rotation for v1. Browser: one opaque HttpOnly Secure SameSite=Strict cookie, DB-hashed, checked on every
request, sliding idle expiry 30 days (lastSeen bump at most once per 10 min), optional absolute expiry (default 365 days,
admin-editable, visible). No rotation => no concurrent-tab rotation races, no family-revocation false positives. Native: one
durable device token in the OS secret store, used only by the native process to mint 60-second single-use window grants that
the native process converts into the partition's cookie (Session API) — the durable token never enters a webview.
Revocation = DB flag + abort registry; downgrade = grantVersion bump + abort of capability-dependent streams.

--- R5 (MEDIUM) Pairing response loss: decided ------------------------------------------------------------------------------
Client generates a 128-bit redemption nonce and sends it with the pairing secret. The device row stores hash(nonce) and the
consumption time. A retry with the same pairing secret + same nonce within 120 s re-issues a fresh session token for the SAME
device (invalidating the previous token) — no new device, no sealed result storage. Any other retry: typed 410 "This
invitation was already used. Ask for a new one." Browser-vs-desktop choice happens before any request (prototype is correct).

--- R6 (MEDIUM) Playback progress concurrency -------------------------------------------------------------------------------
Architecture's (playbackSessionId, sequence, revision) is right; make it concrete: each player mount creates a playbackSessionId;
PUT carries {position, duration, playbackSessionId, seq}; server accepts if seq > lastSeq for that playbackSessionId, and among
different sessions last-writer-wins by server receive time (explicit seek-backwards therefore wins). Scope key
(serverId implicit, profileId, mediaKey = infohash + file index + file length). No max(position).

--- R7 (MEDIUM) Streams, cancellation and external player ---------------------------------------------------------------------
Architecture §9 is correct (cancellable chunked streams for no-Range and /content, admission budgets, 416, suffix ranges, HEAD
starts no torrent wait). Additions: (a) every media response registers with the device's AbortController in the same
synchronous section that validates the session (reserve before first await, per AGENTS); (b) file identity checked at open
(fstat inode/size vs index) and the open descriptor used for all chunks — no re-resolution by path per chunk; (c) external
player grant = opaque token in the PATH (not query) of /media/x/<token>/<filename>, TTL default 6 h, scoped to one file,
Range-capable, revocable, bound to issuing device (revoking the device revokes its grants), Referrer-Policy no-referrer;
copy in UI says "Anyone with this link can play this file until <time>". (d) Documentation and UI say revocation stops
further bytes, never recalls delivered bytes.

--- R8 (MEDIUM) AniList — honest v1 acceptance ------------------------------------------------------------------------------
V7: the provider redirect is the custom scheme tofu://oauth/anilist with an implicit-grant fragment. Supported v1 flows:
  (1) host local window (today's flow); (2) any paired Tofu DESKTOP client with Admin: host creates a pending attempt bound to
  {deviceId, state, 10-min expiry}; the authorize URL opens on the client device; the client OS delivers tofu://oauth/anilist#…
  to the client's native manager, which matches state against its pending attempts per server and POSTs the callback fragment
  to that server with its device credential; host verifies state+device and stores the token host-side. The fragment never
  touches a remote webview. (3) browser-only remote Admin: UI says "Finish connecting AniList in the Tofu app or on Home Mac";
  a "paste the address you were sent to" fallback is offered as best effort (mobile browsers often hide the failed scheme URL),
  not advertised as supported. Registering an https redirect is a later option requiring a new provider client registration.
  Guests: playback never writes AniList; account/editor endpoints are Admin and reject in-process dispatch (S1-B). The existing
  legacy loopback Bun.serve callback (oauth.ts:88) must not be extended to remote use.

--- R9 (MEDIUM) Role matrix — decided (resolves ui.txt §7 "REVIEW DECISION") ------------------------------------------------
Authorities: OWNER = local window on the host or recovery CLI (not a device, cannot be revoked remotely, holds everything).
Device grants: role in {Playback, Management, Administration} + independent flag canDeleteFiles (allowed with Management or
Administration, default off). Issuer rule: an invitation or grant edit may only produce grants that are a subset of the issuer's
effective grants (role rank and canDeleteFiles). An Administration device may edit/revoke only devices whose grants are a subset
of its own; it can never edit itself upward. Owner-only (local authority): storage roots, absolute host paths, watched folders,
certificate/key files, trusted proxy peers, host-native actions. Administration: server settings, integrations (AniList/c411/jev
credentials), automation rules, destinations beneath storage roots, invitations/devices, exposure changes via confirm-or-revert.
Management: add (magnet/upload) into an existing destination ID, pause/resume/priority/reorder, remove torrent entry keeping
files, move between existing destinations only with collision refusal; pausing an existing automation is NOT included in v1.
Delete-files (with Management or Administration): remove-with-files, destination removal with content, destructive automation
options. Playback: safe reads, streaming, own profile/preferences, own logout, own external-player grants.
UI must show canDeleteFiles in every grant summary and disable (with reason) options the issuer does not hold.

--- R10 (MEDIUM) Connection runtime and route switching -----------------------------------------------------------------------
Agree with architecture §7-8. Concrete rules: native supervisor per saved server; route probing only on open/failure/network
change; never move a healthy playing window to a "faster" route; route change = new partition cookie via fresh window grant for
the new origin, page reload at the same path, player resumes from last saved position. Browser tabs never fail over across
origins; they show "Home Mac is reachable at another address" with a link only if that address was learned from an
authenticated descriptor. Public descriptor serverId is a consistency check after TLS validation, never authentication.
Replace tofu-state-sync.tsx's fixed 1 s reconnect with the classified driver (offline / auth / revoked / certificate /
incompatible / busy).

--- R11 (MEDIUM) Remote window composition: decided -------------------------------------------------------------------------
Use the PUBLIC main-process API: BrowserWindow loads a trusted packaged views:// strip (server name, state, picker button,
Servers button), and the main process attaches new BrowserView({windowId, partition:"persist:srv-<serverId>-<deviceId>",
sandbox:true, url, navigationRules:[allow only the selected origin], autoResize}) beneath it. This needs no <electrobun-webview>
container RPC and no SDK fork. Fallback if layering/focus/fullscreen fails a platform proof: pinned upstream BrowserWindow
partition pass-through. Partition purge on Forget via Session.fromPartition().clearStorageData("all") + cookies clear.

--- R12 (LOW-MEDIUM) Secure storage --------------------------------------------------------------------------------------------
Bun.secrets with service "app.tofu.torrents.servers" (dev: ".dev"), name "<serverId>/<deviceId>", persist:"local". On
unavailable/locked keyring: typed native error, UI "Keep this connection until Tofu quits" (memory only) or "Try again"; never
plaintext. Gate G7 must run on the packaged runtime of each platform; if any platform lacks it, that platform ships with the
memory-only mode documented and the release matrix says so.

--- R13 (LOW) UI corrections applied to the prototype (see §9) and further implementation UI requirements ----------------------
Required in implementation (not all prototyped): manager row states for certificate changed / identity changed / incompatible
version / restarting connections / pending-confirmation; unsaved-form guard when switching servers; "Owner (this computer)" row
in Authorized devices instead of a revocable "This Tofu" device; Tailscale "Not checked" before any green state; LAN-direct
host-trust step; confirm-or-revert countdown after remote apply; 44px targets (the "Revoke other devices" 10px link must become
a real button); live region announces only confirmed state changes; capability skeleton on every page with privileged actions;
Playback users never see buttons they cannot use; signed-out page instead of re-showing the pairing page.

3. ANSWERS TO THE REVIEW FOCUS POINTS
=====================================================================
1 SSR authorization. Adopt viewer-invariant SSR (S1) instead of route-level page authorization. Protection argument:
  network admission authenticates every request before Furin routing; every Furin output (documents, /_furin/data frames,
  deferred chunks, 404/error roots, __furinQueries hydration) is built only from Playback-safe in-process reads (Invariant A)
  because privileged endpoints refuse in-process dispatch (Invariant B); device-personal data is browser-only via the unchanged
  client. Permission changes: Playback-safe content needs no recall; private browser caches are cleared on authorizationVersion
  change; long-lived streams abort. Protected Eden is never bypassed or altered. Identity: device + grantVersion stays for
  authorization and cache reset, NOT for idempotency (H3). Keep cursor-only reset; add durable operation receipts for worker
  side effects as architecture §7 says — that part is not overengineering (V4 persists after effect; crash window is real).
2 Native. Manager entry with no static import of src/api (bundle-graph proof); remote content in a main-process partitioned
  sandboxed BrowserView (R11); no generic RPC; partition purge; Bun.secrets gated (R12). BrowserWindow partition is NOT used.
3 Bootstrap listener. Keep it for HTTP mode (R1); do not remove it as v1 work; TLS mode uses native cookie installation (H1).
4 Roles. R9 is the decision; prototype corrected.
5 HTTPS/rebind/Tailscale/proxy/descriptor/pairing/cookies. H1, R2, R3, R5, H5, R10. Tailscale: Tofu owns only one Serve
  mapping it created (store the exact mapping it wrote; on disable remove only an identical mapping; on conflict report and do
  nothing); never Funnel; tailnet reachability is not authentication.
6 Media. R7.
7 UX. R13 plus §9 changes.
8 AniList. R8.
